# 任务 04：失败重试和降级

## 目标

理解 LLM 输出不稳定时，后端需要如何兜底。

完成这个任务后，你应该能说清楚：模型失败不是异常情况，而是生产系统必须默认处理的情况。

## 练习

调用 `POST /v1/structured`，输入：

```json
{
  "messages": [
    { "role": "user", "content": "return_invalid_json" }
  ],
  "schema": { "type": "object" },
  "max_retries": 1
}
```

## 验收标准

- 接口返回 `422`
- 错误信息包含重试失败原因
- 能解释为什么生产系统不能把模型原始输出直接交给下游服务

## 可交付结果

补充一段失败处理策略：

```text
当模型返回非法 JSON 或不符合 Schema 时，Gateway 会先重试。
如果重试后仍失败，接口返回明确错误，避免下游系统接收到不可控数据。
后续可以继续扩展为备用模型、降级回复或人工处理队列。
```

## 进阶

把 `FakeModelProvider` 改成第一次返回非法 JSON，第二次返回合法 JSON，并验证 `retries` 等于 `1`。
